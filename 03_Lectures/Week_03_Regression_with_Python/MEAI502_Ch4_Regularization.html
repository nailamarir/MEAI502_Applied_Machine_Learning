Part 1 · Overfitting

Good algorithms can still perform poorly

So far we have two learning algorithms:

Linear regression

Predict a number, such as a house price.

Logistic regression

Predict a class, such as malignant or benign.

Both work well for many problems. But in some applications they suffer from overfitting and perform very poorly.

Generalization

How well a hypothesis applies to new examples: houses that were not in the training set.

the real test is new data, not the training set
Part 1 · Linear regression example

Predicting housing prices from size

\(\theta_0+\theta_1x\)
Underfit High bias
\(\theta_0+\theta_1x+\theta_2x^2\)
Just right
\(\theta_0+\theta_1x+\theta_2x^2+\theta_3x^3+\theta_4x^4\)
Overfit High variance

Five parameters \(\theta_0,\dots,\theta_4\) for five training examples: the curve can pass through every point.

Part 1 · Overfitting

High bias and high variance

Underfitting = high bias

The algorithm does not even fit the training data well.

It is as if it has a strong preconception that prices vary linearly with size, and it keeps a straight line despite the data showing the contrary.

Overfitting = high variance

A high-order polynomial can fit almost any function. The space of possible hypotheses is too large, too variable.

We do not have enough data to constrain it to a good hypothesis.

Overfitting: if we have too many features, the learned hypothesis may fit the training set very well, with \(J(\theta)=\frac{1}{2m}\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)^2\approx 0\), but fail to generalize to new examples (predicting prices of new houses).

Part 1 · Logistic regression example

Overfitting happens in classification too

\(g(\theta_0+\theta_1x_1+\theta_2x_2)\)
Underfit High bias
\(g(\theta_0+\theta_1x_1+\theta_2x_2+\theta_3x_1^2+\theta_4x_2^2+\theta_5x_1x_2)\)
Just right
\(g(\theta_0+\theta_1x_1+\theta_2x_1^2+\theta_3x_1^2x_2+\theta_4x_1^2x_2^2+\cdots)\)
Overfit High variance

\(g\) = sigmoid. With many high-order terms, logistic regression contorts itself to classify every training tumour correctly, and is unlikely to generalize. Later we will learn tools to diagnose this.

Part 1 · Addressing overfitting

We cannot always plot the hypothesis

With one or two features we can plot the hypothesis and pick a sensible polynomial degree.

But real problems often have many features. Then it is hard to visualize the data and decide which features to keep.

Many features + little training data → overfitting becomes a problem.

Part 1 · Addressing overfitting

Two main options

1 · Reduce the number of features

  • Manually select which features to keep
  • Model selection algorithms decide automatically (later in the course)

Downside: throwing away features also throws away information about the problem.

2 · Regularization

  • Keep all the features
  • Reduce the magnitude (values) of the parameters \(\theta_j\)

Works well when we have many features, each contributing a bit to predicting \(y\).

Penalizing large parameters

Part 2 · Intuition

Suppose we penalize \(\theta_3\) and \(\theta_4\)

\[\min_\theta\ \frac{1}{2m}\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)^2 \;{\color{#dc2626}+\,W\,\theta_3^2+W\,\theta_4^2}\]
Penalty W

With W = 1000, the only way to keep the cost small is \(\theta_3\approx0\), \(\theta_4\approx0\).

we are left with (almost) a quadratic!
Part 2 · The idea

Small parameter values

Small values for \(\theta_0,\theta_1,\dots,\theta_n\)

  • a simpler, smoother hypothesis
  • less prone to overfitting

Why small values mean "simpler" is easiest to see when you implement it yourself in the lab.

Housing, with 100 features

Features: \(x_1,x_2,\dots,x_{100}\)
Parameters: \(\theta_0,\theta_1,\theta_2,\dots,\theta_{100}\)

Unlike the polynomial example, we don't know which parameters belong to the less relevant features.
So we shrink all of them.
Part 2 · Cost function

The regularized cost function

\[J(\theta)=\frac{1}{2m}\Big[\;{\color{#1d4ed8}\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)^2}\;+\;{\color{#dc2626}\lambda\sum_{j=1}^{n}\theta_j^2}\;\Big]\qquad \min_\theta J(\theta)\]

Goal 1 · fit the data

The usual squared error: fit the training set well.

Goal 2 · keep θ small

The regularization term: keeps the hypothesis simple to avoid overfitting.

λ · the balance

The regularization parameter controls the trade-off between the two goals.

By convention the sum starts at \(j=1\): we do not penalize \(\theta_0\). In practice, including it makes very little difference.

Part 2 · Check

What if \(\lambda=10^{10}\)?

Correct: all of \(\theta_1,\dots,\theta_n\to0\), so \(h_\theta(x)\approx\theta_0\), a flat line.

\(h_\theta(x)=\theta_0+\cancel{\theta_1x}+\cancel{\theta_2x^2}+\cancel{\theta_3x^3}+\cancel{\theta_4x^4}\) high bias: "prices are just \(\theta_0\)".

Choose λ with care. Model selection (later) gives ways to choose λ automatically.

Part 3 · Gradient descent

Gradient descent with regularization

Repeat {

\(\theta_0 := \theta_0-\alpha\,\dfrac{1}{m}\displaystyle\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)x_0^{(i)}\)  θ₀ is not penalized
\(\theta_j := \theta_j-\alpha\Big[\dfrac{1}{m}\displaystyle\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)x_j^{(i)}{\color{#dc2626}\;+\;\dfrac{\lambda}{m}\theta_j}\Big]\)  \(j=1,2,\dots,n\)

}

The term in square brackets is exactly \(\dfrac{\partial}{\partial\theta_j}J(\theta)\) for the new, regularized \(J(\theta)\).

Part 3 · Gradient descent

Every step shrinks \(\theta_j\) a little

\[\theta_j := \theta_j\,{\color{#dc2626}\Big(1-\alpha\frac{\lambda}{m}\Big)}-\alpha\frac{1}{m}\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)x_j^{(i)}\]

Shrink

\(1-\alpha\frac{\lambda}{m}\) is a number a little less than 1, like 0.99: \(\theta_j\) moves slightly toward zero.

Then the usual step

The second part is exactly the original gradient descent update.

Part 3 · In Python

Regularized linear regression in NumPy

def cost_reg(theta, X, y, lam): m = len(y) err = X @ theta - y reg = lam * np.sum(theta[1:] ** 2) # skip theta_0 return (err @ err + reg) / (2 * m) def grad_reg(theta, X, y, lam): m = len(y) g = X.T @ (X @ theta - y) / m g[1:] += (lam / m) * theta[1:] # not theta_0 return g def gradient_descent(X, y, lam, alpha=0.01, iters=1000): theta = np.zeros(X.shape[1]) for _ in range(iters): theta -= alpha * grad_reg(theta, X, y, lam) return theta

X has a column of 1s

so theta[0] is \(\theta_0\), and theta[1:] are the penalized parameters.

scikit-learn

Ridge(alpha=lam) fits the same model. Ridge is the name for L2-regularized linear regression.

Part 4 · Cost function

Regularizing the logistic cost

With high-order polynomial features, or just many features, logistic regression can overfit:

\[h_\theta(x)=g\big(\theta_0+\theta_1x_1+\theta_2x_1^2+\theta_3x_1^2x_2+\theta_4x_1^2x_2^2+\theta_5x_1^2x_2^3+\cdots\big)\]
\[J(\theta)=-\frac{1}{m}\sum_{i=1}^{m}\Big[y^{(i)}\log h_\theta(x^{(i)})+(1-y^{(i)})\log\big(1-h_\theta(x^{(i)})\big)\Big]{\color{#dc2626}\;+\;\frac{\lambda}{2m}\sum_{j=1}^{n}\theta_j^2}\]
Even with many parameters, keeping them small gives a more reasonable decision boundary.

Part 4 · Gradient descent

Gradient descent: looks the same, but isn't

Repeat {

\(\theta_0\): same update as before (not penalized)

\(\theta_j := \theta_j-\alpha\Big[\underbrace{\dfrac{1}{m}\displaystyle\sum_{i=1}^{m}\big(h_\theta(x^{(i)})-y^{(i)}\big)x_j^{(i)}{\color{#dc2626}\;+\;\dfrac{\lambda}{m}\theta_j}}_{\frac{\partial}{\partial\theta_j}J(\theta)}\Big]\)  \(j=1,\dots,n\)

}

Cosmetically identical to regularized linear regression.
A different algorithm: here \(h_\theta(x)=\dfrac{1}{1+e^{-\theta^Tx}}\).
Wrap-up

Key takeaways

1. Underfit = high bias; overfit = high variance: fits training data, fails on new examples.

2. Fix overfitting by reducing features or by regularization (keep features, shrink θ).

3. Add \(\frac{\lambda}{2m}\sum_{j=1}^{n}\theta_j^2\) to the cost. \(\theta_0\) is not penalized.

4. λ too small → still overfits; λ too large → underfits.

5. Gradient step: \(\theta_j\) shrinks by \(1-\alpha\frac{\lambda}{m}\), then the usual update.

6. Logistic regression: same update form, but \(h_\theta\) is the sigmoid.

With linear regression, logistic regression, gradient descent and regularization, you can already apply ML to many real problems. Next: more powerful non-linear classifiers.
